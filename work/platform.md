# 平台

## 1. 背景与问题

组织与个人对确定性的要求相反。组织要可预期，才能协作与追责；个人要保留困惑与未完成，才谈得上探索。用同一套写法处理两边，必然一边受损。

## 2. 判断

组织要刚性，个人要留困惑。

组织侧：规则确定、可预期，变更走版本。个人侧：档案保留困惑、未完成与前后矛盾。

## 3. 机制

组织的产出要能被别人接手，规则一旦含糊，协作成本由所有人承担。个人的探索发生在结论之前，过早收束会把还没想清的部分删掉，下一次又从零开始。两边要的确定性不在同一个时间尺度上，因此不能共用一套收纳标准。

## 4. 边界

这条分界只管「写下来的规则与档案」，不管组织内部的探索性工作。组织也需要试验，只是试验要放在实验室或案例里，验收后再升为规则。

09-26 按这条分界整理个人档案后，档案质量明显变好，算一次实测；但它还不足以证明分界在所有资产上都成立，仍按假说对待。

## 5. 结论

判断一份材料该多硬，先看它服务谁：给组织协作用，写到可预期；给自己探索用，允许留着没想清的部分。
