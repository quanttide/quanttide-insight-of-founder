# 开源公司与复制组织

## 1. 背景与问题

「开源公司」通常指三种做法：代码开源、卖服务；公开内部文档、建立信任；社区贡献者兼职干活、降低研发成本。三种都停在商业策略或劳动力套利，没有回答一个问题：公司本身能不能像开源软件一样被 fork、修改、重新部署。

## 2. 判断

开源的对象是生产方式，不是某个成品。人才、流程、文化本来带不走；写成训练体系、工作流与契约之后，三样都能被复制。复制不是开分公司，是分发一个可运行的组织实例。

## 3. 机制

人才、流程、文化之所以不可复制，是因为它们停在经验、默契与氛围里。写成可执行的训练、可运行的规则与可验收的契约之后，复制不再依赖原班人马。主干因此收窄为价值判断、验收标准、资产分类法与版本纪律；创新研发、人才训练、服务交付与生态扩展交给社区。

主干管名词，社区管动词；工程层的人机分工，放大到组织层就是这个样子。

## 4. 边界

这是假说。目前只有雏形，没有跑通过一次完整复制。内核标准、通信标准这类类比只能说明方向，不能拿来当验证。

推翻它的情形很具体：fork 出去的实例在离开原团队后维持不住主干质量；或者「标准」最终仍要靠原班人马逐次解释。

## 5. 结论

公司被复制之后成为标准。量潮若走通，最终交付的是一套可部署的组织协议：任何人想办一个求真务实的知识型组织，都能取一份到自己领域跑起来。
