# 确定性

## 1. 问题

同一场战斗，两次运行必须给出同一个结果。否则夹具回归、迷雾比对、AI 决策追踪都失去基准，越往后返工越贵。

## 2. 定义

确定性指：同一组命令配同一个主种子，重跑两遍，事件流逐字节一致。

主种子在开局注入一次，按名字派生子流。每个消费点只能从注册过的子流取随机数，未注册即报错。子流不提供重置，避免同一段逻辑在不同回合拿到同一串随机数。

事件流里的每条事件都要能追到取数的子流与回合，不允许出现没有解释的随机性。

## 3. 验证

### 3.1 双跑比对

同一想定、同一命令、同一主种子跑两遍，逐事件比对。差异为零才算通过；非零要指出第一处偏离的回合、相位与两侧事件原文。

### 3.2 改种子必偏离

换一个主种子重跑，比对结果必须出现偏离，并指出第一偏离点。两次都一致，说明种子没有真正接入。

### 3.3 静态检查

引擎包禁用浮点，数值一律用整数，比如米、厘、万分比。需要比例时用万分比整数，不用小数。

## 4. 原则

- 浮点跨平台不保证一致，确定性要求把浮点挡在结算之外。
- 大模型只碰文字，不进结算闭环；一旦进入，确定性与可复算同时失效。
- 随机数只从参数传入的子流取，不读全局状态，也不自行调用时钟。
- 确定性检查进 CI，每次提交都跑；红了先回滚，不用临时容忍换进度。

## 5. 结论

确定性不是性能或洁癖，而是全部验收的前提。它立不住，后面每一层都只能在流沙上断言。
