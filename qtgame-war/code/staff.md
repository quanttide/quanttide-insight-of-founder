# 参谋翻译与追问

## 1. 问题

玩家下的是战役语言：攻龙王店、阻邱清泉于杞县以东。引擎只认单位、动作、目标与时限。两者之间需要一层翻译，还要让玩家知道参谋理解成了什么。

## 2. 定义

翻译分两级：高层命令先展开成纵队任务，再展开成引擎命令。

展开用规则模板，不用写死的条件分支。模板、可用动作与合法性条件都进参数表。

每条命令展开后先做合法性预检。预检失败生成“无法执行”事件，决断作废；结算时前提消失，生成拒收事件，回合继续。两种失败都不静默丢弃。

追问是只读接口：点选一个敌军建制，返回估计位置、估计实力、置信度，以及支撑这条估计的情报。玩家可以看到参谋的判断链，也可以选择不信。

参谋回执把理解结果返回给玩家确认；确认之后才进入结算。

## 3. 验证

- 同一高层命令展开两次，结果一致。
- 非法命令被拒绝，错误信息能指出缺哪个单位、哪个目标或哪个时限。
- 追问返回的每条估计都能追到情报；没有情报支撑时明确说“不知道”。
- 换一套模板或参数，命令展开变化，引擎代码不动。

## 4. 原则

- 翻译只做展开与预检，不做判断；判断留在决策层。
- 预检失败与结算拒收都要留记录，否则复盘出现空白。
- 追问只读信念，不读真相；参谋不该比玩家多知道。
- 模板可换，命令语言不变；换玩法不换契约。

## 5. 结论

参谋层让“下命令”这件事在游戏里成立：玩家说得出口，引擎接得住，中间的理解偏差还能被看见。
