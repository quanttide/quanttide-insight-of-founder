# 驱动层

## 1. 问题

同一套机制要能由不同的人来开：脚本、作者本人、第一次接触的读者、图形界面。每换一个入口就改一次机制，前面的断言全部作废。

## 2. 定义

驱动层分四级：

- L1 脚本：自动决策喂命令，用于批量对局与回归。
- L2 命令行：作者本人下令、读报、追问，用于完整对局。
- L3 文本界面：新读者只读报告，用于复述测试。
- L4 图形界面：Flutter 接入，用于正式游玩。

四级共用同一条命令通道与同一份报告。入口只做输入适配，不含结算逻辑，也不读真相。

人类命令插头接在决断相位：有人输入时覆盖自动决策，输入格式与自动决策的输出完全一致。无人输入时，同一张相位表自然走自动决策。

两种玩法共用同一套结算：互动剧本模式以报告与追问为主，上帝视角模式直接操作棋子。

## 3. 验证

- 换驱动层，机制代码零改动。
- 人类输入与自动决策的输出走同一个校验入口。
- L4 的每条界面信息都能对应到一个命令输出；对应不上的，说明界面在偷读真相。
- L1 批量与 L2 人工在同一想定上得到同构的档案。

## 4. 原则

- 玩家是一个接口，不是一个界面。
- 机制不跟着界面走；界面要什么，先看命令通道能不能表达。
- 入口不读真相；能读，迷雾与公平一起失效。
- 先有命令行，再有界面；命令行是机制的第一个真实用户。

## 5. 结论

驱动层换的是方向盘，不是发动机。发动机不变，换谁开都不影响这场仗怎么算。
