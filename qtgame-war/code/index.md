# 迷雾中的司令部 · 实现

玩法层的判断见 [../game/index.md](../game/index.md)。

## 假说

- **确定性是全部验收的前提**：同一组命令配同一个随机种子重跑两遍，事件流逐字节一致；这一步不立住，后面每一段的断言都失去手段，越往后返工越贵。出处：四份游戏路线图稿件对齐时的判断（2026-10-25）。
- **档案是迷雾可被测量的前提**：事件与报告在关卡处分开，上层只读报告；没有这层隔离，复盘无从对照，也判断不了迷雾有没有生效。出处：同上。

- **驱动层可以换人，机制不变**：脚本、命令行、图形界面只是同一套机制的三个入口；机制一旦跟着界面走，前面积累的断言全部作废。出处：同上。
- **大模型只能停在文字层**：一旦进入结算闭环，确定性与可复算同时失效。出处：同上。

- **契约成立只能靠换桩证明**：两侧各对着假实现开发，任一侧换成真实现而另一侧零改动，契约才算立住；文档把格式写清不算数。出处：《系统契约》路线图阶段 1 验收（2026-10-25）。
- **引擎必须做哑**：只认命令、只说真相，认知与翻译全留在指挥部侧；引擎一旦懂意图，互动剧本与兵棋推演就无法共用同一套结算。出处：系统契约路线图、开发路线图 M3（2026-10-25）。
- **类型隔离靠编译器，不靠文档**：事件与报告在关卡处分开后，上层源码出现事件类型即失败；写成 lint 规则，比任何规范都可靠。出处：《架构设计说明书 v1.1》评审 §7.3。
- **命令失效必须留档**：预检失败与结算拒收都生成事件，不静默丢弃；否则复盘时「我下了命令，为什么没执行」无从解释。出处：同上 §3.4。
- **结算只交增量补丁**：各阶段结算返回变更、由世界状态合并写入，与事件流同构；整树快照会让「这次结算改了什么」重新变成猜。出处：同上 §2.2。
- **禁用浮点是确定性的前提**：`double` 跨平台不保证一致，引擎数值一律整数（米、厘、万分比）；第一天就上 lint，后期补成本极高。出处：《迷雾中的司令部》开发路线图 M1（2026-10-25）。
- **参数不进代码**：新增数值一律进参数表并记指纹，代码里出现裸数值即违例；否则每次分布漂移都无法归因到改了哪里。出处：开发路线图跨里程碑纪律。
- **验收能力必须领先本体半步**：本体换真实现之前，对应断言先长出来等着；两条线不咬合，就视为该阶段未完成。出处：《验收标准》路线图（2026-10-25）。
- **金标准只能人工把关**：夹具可以由脚本生成，期望结果必须人复核；金标准错了，整套验收全盘皆错。出处：同上 V0。


- **校准比考证便宜**：历史参数用区间、来源性质、三视角交集交付，由敏感性分析兜底；绝对精度不重要，只要历史结果在参数带内能涌现。出处：《战场系统》路线图（2026-10-25）。
