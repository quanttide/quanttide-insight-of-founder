# 迷雾中的司令部 · 实现

## 1. 一句话

把真相和认知分开：真相只有一份，认知每人一份；中间只留命令与事件两条通道。

## 2. 两条线

真相线负责结算：部队怎么动、在哪里接敌、打掉多少、补给够不够。它只认命令，不猜意图，结果写成事件。

认知线负责判断：哪些事件看得见、什么时候送到、送到的内容偏了多少、据此信什么。玩家一条，敌军 AI 一条，走同一套管线，只是输入和参数不同。

两条线在关卡处交接。关卡是唯一的转换点：事件在这里翻成报告，报告只进认知线；命令从认知线下发，经参谋翻译回到真相线。

## 3. 五条约束

### 3.1 可复算

同一组命令配同一个种子，重跑两遍，事件流逐字节一致。数值用整数，浮点跨平台不保证一致；大模型只碰文字，不进结算闭环。

### 3.2 可替换

两侧先对着假实现开发，再把一侧换成真实现，另一侧一行不改。还能跑，边界才算成立。引擎因此要做哑，事件与报告的类型隔离要由编译器拦住。

### 3.3 可复盘

事件与报告分开，命令失效也留档，结算只交增量。一局打完，能指出第一处偏离发生在哪个回合、哪个相位。

### 3.4 可验收

验收能力比本体早半步：真实现落地之前，对应的断言先长出来。夹具可以脚本生成，期望结果必须人复核；自动断言之外，还要有人完整打一局。

### 3.5 可调参

数值不进代码，一律进参数表并记指纹。历史参数不求点值，用区间、来源性质和三视角交集交付，由敏感性分析兜底。

## 4. 顺序

先定契约，再做假桩闭环，然后填真引擎，接着填认知与敌军 AI，最后接界面。前一关不过，不进下一关。每一步都要留下能重跑、能对照、能替换的东西。

## 5. 判断标准

换掉一边，另一边不用改。重跑两遍，事件流一致。一局打完，查得到第一处偏离。数值改了，看得出漂移从哪来。自动断言全绿之后，人还能打完一局，并说清自己当时信了什么。
