# 回合与相位

## 1. 问题

一局游戏由许多回合组成。每个回合里，谁先动、谁后动、什么时候写记录，必须有唯一顺序；否则同一份命令在不同实现里会走出不同结果。

## 2. 定义

一个回合走三拍：下令、结算、读报。

下令：决策层定下决心，参谋把高层命令展开成引擎命令。

结算：引擎按相位表依次处理机动、接敌、战斗、损耗与补给。

读报：事件过关卡变成报告，按通信时间送达，进入信念。

相位表是回合内唯一的调度入口。它只点名各层的公开入口，不点名内部模块；层内顺序由该层自己负责。

最小相位表为五段：friendly_decide、command_dispatch、movement_resolve、event_dispatch、archive_turn。完整表再加入 combat_resolve、supply_evaluate 与敌方各相位。敌方相位在单机阶段先占位，接入敌军 AI 后填充。

## 3. 验证

- 下令到读报的闭环能无人干预跑完一个回合。
- 同一命令、同一种子双跑，事件流逐字节一致。
- 中途替换任一侧为真实实现，另一侧零改动。
- 相位表带指纹；改表即改指纹，旧档案能看出用的是哪一版。

## 4. 原则

- 状态机最先写，其他模块的调用顺序都挂在它上面。
- 相位表只调度公开入口，不能绕过关卡直接调内部模块。
- 关卡与记录点集中在主循环里，不分散到各层；审计只看一处。
- 人机对局与双 AI 对局共用同一张相位表；无人输入时，决断相位自然走自动决策。

## 5. 结论

回合结构不是界面问题，而是确定性的一部分。顺序定死，后面每一层才有稳定的输入与输出。
