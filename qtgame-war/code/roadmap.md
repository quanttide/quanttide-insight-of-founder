# 开发顺序

## 1. 问题

这个项目同时有引擎、认知、AI、界面与验收五条线。一起铺开，任何一条出问题都看不出是谁的问题；按依赖排序，每一段结束时都能留下可运行、可验证的东西。

## 2. 定义

顺序按四个能力切分：

- 可复算：引擎从界面里拆出来，同种子双跑零偏离。
- 可复盘：五卷齐备，事件与报告分开，第一偏离点能定位。
- 可对弈：认知管线与敌军 AI 落地，双 AI 能跑完整战役。
- 可交付：人类命令插头、两种玩法、参数扫描与仪表盘到位。

每一段有自己的验收标准；前一段不过，不进下一段。

## 3. 验证

- 每段结束时，能明确指出它消除了哪一条差距，而不是“又前进了一点”。
- 可复算段：双跑一致，改种子必偏离。
- 可复盘段：注错后三分钟内定位第一偏离。
- 可对弈段：性质断言全过，双 AI 跑完整战役。
- 可交付段：真人经命令行打完整一局，档案齐备。

## 4. 原则

- 确定性破了，不用临时容忍换进度；先修地基。
- 验收系统与本体同步交付；两条线不咬合，视为该段未完成。
- 最大的不确定项先写性质断言，再写实现；不用“感觉对不对”当门槛。
- 每段封版即停，剩余打磨进待办，不阻塞下一段。

## 5. 结论

开发顺序不是工期表，而是依赖关系。每一段都在为下一段买自由度；顺序错了，后面的自由都要用返工来换。
