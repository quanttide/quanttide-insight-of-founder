# 参数与校准

## 1. 问题

兵棋的数值永远不准。兵力、战损比、补给消耗，史料之间互相矛盾，精确到个位既做不到，也没有意义。问题不是找到真值，而是让数值可用、可改、可复核。

## 2. 定义

参数分两层：引擎参数与想定参数。两层都放在代码之外，新增数值一律进参数表，并记版本指纹；代码里出现裸数值即违例。

历史参数用参数卡交付。每张卡给出区间，不给点值：

- band：上下界；
- knowledge_basis：记忆来源的性质，如官方战史、回忆录、对方战史、科普读物、纯估计；
- confidence：高、中、低；
- note：一句说明，写清怎么算与可疑处。

同一参数用三个视角独立抽取：本方战史、对方战史、中立研究。三个区间求交集，交集即置信带；没有交集就取并集并标低置信，由作者裁决。

流转只有两步：AI 提案，作者批准。作者对每个区间说“行、改、这条我不知道”，不需要自己查书。

## 3. 验证

- 改参数不改代码，想定结局随之变化。
- 每个参数都能追到一张卡与一次批准。
- 敏感性分析：参数在带内变动时，历史锚点仍然成立；失效临界值要能指出。
- 参数扫描产出曲线，跨版本可比较，漂移方向可见。

## 4. 原则

- 校准比考证便宜；绝对精度不重要，历史结果能在参数带内涌现才重要。
- 区间可以宽，点值不可编；记不清就标低置信，不装懂。
- 作者有权把任何区间手动放宽一档。
- 参数调不出历史，先怀疑机制，不继续拧数字。

## 5. 结论

参数表不是数据的仓库，而是可复核的假设集合。它让调参变成实验，而不是手感。
