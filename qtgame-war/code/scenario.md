# 想定文件

## 1. 问题

一场战役要能换、能改、能复现。地图、初始部署、援军、胜负条件如果写死在代码里，改一场战役就要改一次引擎。

## 2. 定义

想定是一份数据文件，至少包含四部分：

- 地图拓扑：六角格、地形、通行代价；
- 初始部署：双方单位、番号、位置、兵力；
- 主种子：这一局随机流的起点；
- 胜负条件：什么算赢，什么算输。

完整想定再增加援军波次与后果槽位。援军波次按回合触发，写进数据而不是代码；后果槽位先留结构，军事、消耗、政治三线在后续填充时不用改档案格式。

想定与参数表都带版本指纹。指纹不同，旧档案仍能看出当时用的是哪一版。

## 3. 验证

- 想定加载通过校验，指纹落档。
- 改 JSON 能改结局，引擎代码零改动。
- 同一想定、同一种子双跑，事件流一致。
- 新增一场战役不新增代码分支。

## 4. 原则

- 想定只描述世界，不描述玩法；玩法差异进参数与模板。
- 结构先留槽位，内容后填；等实现时再改格式，旧档案就废了。
- 番号沿用现有命名，不另造一套。
- 想定是第一个验收对象：它跑不通，后面所有机制都没有输入。

## 5. 结论

想定文件把“换一场战役”从代码任务变成数据任务。它是引擎的第一个真实用户，也是参数与验收的共同入口。
